-  객체지향 4대 원칙

객체지향 프로그래밍은 프로그램을 어떤 데이터 인풋에 따라 처리하고 아웃풋을 내는 instruction의 목록을 보는 시각에서 벗어나 독립적인 부품(객체)들의 조합으로 파악하고자 하는 패러다임입니다. 이는 소프트웨어를 설계할 때 코드 변경을 최소화하고 재사용을 통해 간결하고, 유지 보수를 편하게 할 수 있게 합니다. 4대 원칙은 추상화, 상속, 다형성, 캡슐화입니다. 추상화는 객체에서 본질적이고 공통적인 부분만 추출하여 표현하는 것입니다. 예를 들어 차와 오토바이는 모두 앞으로 간다는 공통점이 있습니다. 그렇다면 이동수단이라는 클래스에 앞으로 간다에 대한 핵심적인 역할만 규정해두고, 실제적인 구현은 차와 오토바이를 구현하는 각자의 객체에서 하도록 설계하는 것이 추상화 입니다. 상속은 상위 클래스(부모 클래스)의 속성과 동작을 하위 클래스(자식 클래스)가 상속받아 재사용하는 개념입니다. 코드의 중복을 줄이고 유지 보수를 쉽게 할 수 있게 합니다. 다형성은 같은 메서드를 여러 방식으로 구현할 수 있는 개념입니다. 같은 함수라도 파라미터를 다르게 하는 오버로딩이나 부모 클래스와 자식 클래스의 정의를 다르게 하는 오버라이딩 등이 있습니다. 캡슐화는 객체의 데이터와 동작을 하나로 묶고 접근 제어자와 같은 로직을 통해 외부에서 접근하지 못하도록 제한하는 것입니다. 데이터를 직접 건드리는 로직을 숨기고 외부에서 볼 수 있는 로직을 통해 수정할 수 있도록 설계하는 것입니다.

- 프로세스와 스레드

프로세스는 하나의 프로그램이 동작하기 위해 OS에 끌어오는 자원들이 들어있는 작업의 단위입니다. 스레드는 프로세스가 할당 받은 자원들을 이용하는 실행의 단위입니다. 예를 들어 우리는 크롬을 실행하고 안에서 파일을 다운 받고 게임을 하고 인터넷 서핑을 합니다. 하나의 프로세스 안에서 여러가지 작업들이 동시에 진행되기 때문에 가능한 것인데 이러한 일련의 작업들을 스레드라고 합니다. 하나의 프로그램 실행 속에서도 여러 프로세스가 만들어질 수 있고 그 속에 여러 스레드가 생길 수 있습니다. 프로세스가 만들어질 때 코드(텍스트), 데이터, 스택, 힙 영역으로 메모리가 할당됩니다. 하나의 프로세스 안에 여러 스레드가 동작할 때 각 스레드는 각자의 스택을 가집니다. 나머지 메모리는 공유 자원으로 모든 스레드가 가져와 읽고 쓸 수 있습니다. 당연히 여러 스레드가 공유 자원에 동시에 접근할 경우 Race Condition이 발생할 수 있어 동기화가 필요합니다. 멀티프로세스는 프로세스 간 메모리가 완전히 독립되어 안정적이지만 Context Switching 비용이 크고, 멀티스레드는 메모리를 공유해 효율적이지만 동기화 문제가 생길 수 있습니다.

- TCP와 UDP

네트워크 계층에서 전송 계층에서 데이터를 보내기 위한 프로토콜(제약)입니다. Transmission Control Protocol은 인터넷 상에서 IP와 함께 메시지 형태로 데이터를 보내는 프로토콜 입니다. IP가 데이터의 배송 주소를 기록한다면 TCP는 패킷을 추적하고 관리합니다. 우선 패킷을 보내기 위한 논리적 경로를 배정합니다. handshaking 과정을 통해 전송하기 전 연결을 확인, 해제하여 신뢰성을 보장합니다. 이 과정에서 데이터의 흐름이나 혼잡도를 제어합니다. 따라서 파일 전송 같은 신뢰성 있는 전송이 중요할 때 사용됩니다. User Datagram Protocol은 말 그대로 데이터그램 단위로 처리합니다. 데이터그램은 독립적인 관계를 가진 패킷이란 의미입니다. 따라서 패킷은 다른 경로로 전송되고 checksum 수준의 필드로 최소한의 오류만 검출합니다. 때문에 속도가 빠르고 네트워크 부하가 적다는 장점이 있지만 신뢰성 있는 데이터 전송을 보장하지는 못합니다.

- http와 https

http는 웹에서 브라우저(클라)와 서버가 TCP 위에서 데이터를 주고 받는 프로토콜입니다. 전송 계층보다 윗 단계인 애플리케이션 레벨의 프로토콜로 상태를 가지지 않는 Stateless 프로토콜입니다. 하지만 암호화가 되지 않은 데이터를 전송하기 때문에 제 3자가 정보를 조회할 수 있어 이러한 문제를 해결하기 위해 https가 등장하게 되었습니다. 접미어 s는 secure의 뜻을 가집니다. 즉 http에 암호화가 추가된 프로토콜 입니다. 암호화에는 대칭키와 비대칭키 방식이 있다. 예를 들어 11과 13이라는 키가 있고 143이라는 숫자가 전송될 때 제 3자는 143이라는 숫자를 11과 13으로 인수분해하는 데 오랜 시간이 걸리지만 11 또는 13 키를 가진 클라와 서버는 쉽게 풀 수 있는 것과 비슷한 원리이다. 실제로 브라우저는 서버로 최초로 연결 시도를 한다. 서버는 공개키를 브라우저에게 전달하고 브라우저는 공개키의 유효성을 검증하여 대칭키(세션키)를 발급한다. 브라우저는 대칭키를 서버의 공개키로 암호화하여 서버로 전송하면 서버는 복호화 하여 대칭키를 얻는다. 이렇게 서버와 클라는 동일 대칭키를 공유하므로 이를 이용해서 데이터를 전달한다.

- 배열과 링크드리스트

Array는 메모리 상에 연속된 공간에 데이터가 저장되는 자료구조입니다. 다음 인덱스의 값이 물리적으로 가깝게 있기 때문에 `a[5]`에 접근할 때 시작 주소에 타입의 바이트 크기만큼 오프셋을 더해 바로 접근할 수 있습니다. 따라서 인덱스 접근이 O(1)로 매우 빠릅니다. 하지만 크기를 선언 시점에 고정해야 하고, 중간에 요소를 삽입하거나 삭제하려면 뒤의 데이터를 모두 이동시켜야 해서 O(n)의 비용이 듭니다.

LinkedList는 각 노드가 데이터와 다음 노드의 주소를 함께 저장하는 구조입니다. 물리적으로 연속되어 있지 않고 포인터로 연결되어 있어서 특정 인덱스에 접근하려면 처음부터 순차적으로 따라가야 해 O(n)이 걸립니다. 대신 중간 삽입이나 삭제는 주변 노드의 포인터만 바꾸면 되기 때문에 O(1)에 가능하고, 크기를 동적으로 조절할 수 있다는 장점이 있습니다.

다만 LinkedList는 각 노드마다 포인터를 위한 추가 메모리가 필요하고, 메모리가 연속되어 있지 않아 CPU 캐시 효율이 떨어집니다. 반면 Array는 연속된 메모리 덕분에 캐시 친화적이라 실제 성능 면에서도 유리한 경우가 많습니다.

정리하면 **접근이 잦고 크기가 고정적이면 Array**, **삽입·삭제가 잦고 크기가 유동적이면 LinkedList**가 적합합니다.


- 해시 테이블

해시 테이블은 key-value 쌍으로 데이터를 저장하기 위한 자료구조 입니다. 해시 테이블은 key 값에 해시 함수를 적용해 고유 인덱스를 생성합니다. 이 인덱스를 활용해 인덱스 번호의 배열, 버켓에 있는 value 값을 가져온다. 이 때 해시 함수에 따라 인덱스 값이 겹칠 수 있다 예를 들어 모듈러 4 연산을 하는 해시가 있다면 5의 해시 값은 1이고 9 역시 1인 고유 인덱스를 가지게 된다. 이를 해시 충돌이라고 한다. 이를 해결 하기 위해서는 버캣에 추가 메모리를 사용하여 chaining 방식으로 value들을 관리할 수 있다. 이는 해시테이블의 확장이 필요없고 손쉽게 구현, 삭제, insert를 할 수 있다는 장점이 있다. 하지만 데이터가 많아질 수록 동일 인덱스, 동일 버캣에 chaining이 많아지고 효율성이 감소한다. 다른 방식으로 비어있는 해시 테이블의 공간을 활용하는 방법이 있다. 현재 인덱스로부터 특정 offset만큼 이동하여 비어있는 버캣에 저장하는 방식이다. 이러한 offset을 선정하는 방식에는 고정된 linear 값을 이용하거나, 제곱, 해싱을 다시 해싱하는 여러가지 방법론들이 있다. 

- 지도, 비지도, 강화학습

지도 학습은 정답이 있는 labelled data를 대상으로 train data를 구성하는 것이다. 이후 test data를 통해 성능을 평가한다. 하지만 이렇게 데이터 셋에 대해 정답을 매기는 레이블링 작업은 데이터의 양에 비례해 비용이 크다는 단점이 있다. 이에 대한 대안으로 비지도 학습이 있다. 비지도 학습은 정답이 없는 데이터를 분석하면서 패턴을 찾아내 데이터를 그룹화하는 알고리즘을 말한다. 예를 들면 클러스터링이나 차원 축소 등이 있다. 강화학습은 이와 약간 다르다. 주어진 환경과 소프트웨어 수준의 에이전트, 플레이어, 주체?가 있다. 이 행동에 따른 결과 값이 보상으로 주어지고이 보상이 최대의 결과값을 지향하기 위해 학습하는 것을 강화학습이라고 한다. 강화학습에서는 이 에이전트의 유한상태머신에 대한 정의와 보상에 대한 수치적인 설계가 중요하다.

- overfitting과 underfitting

Overfitting은 모델이 훈련 데이터에 과도하게 맞춰져 새로운 데이터에서 성능이 떨어지는 현상입니다. 수학 문제를 연습할 때 연습 문제의 답을 외워버리면 연습에서는 100점이지만 실제 시험에서는 틀리는 것과 비슷합니다. 데이터 전체의 경향성이 아니라 노이즈까지 학습해버린 상태로 볼 수 있습니다.

방지 방법은 크게 세 가지입니다. 첫째, 모델을 단순화하는 것으로 파라미터 수를 줄이거나 Layer를 줄이는 방식입니다. 둘째, 정규화 기법으로 Dropout은 학습 때마다 일부 뉴런을 무작위로 비활성화해 특정 뉴런에 의존하지 않게 합니다. L1, L2 Regularization은 손실 함수에 가중치 크기에 대한 페널티를 추가해 과도한 학습을 억제합니다. 셋째, 데이터를 늘리는 방법으로 Data Augmentation이나 검증 데이터 성능이 떨어지면 학습을 멈추는 Early Stopping이 있습니다.

반대로 Underfitting은 모델이 훈련 데이터조차 충분히 학습하지 못한 상태입니다. 모델이 너무 단순하거나 학습이 부족할 때 발생합니다. Underfitting은 Bias가 높고 Overfitting은 Variance가 높은 상태로, 둘 사이의 균형을 맞추는 것이 머신러닝의 핵심 과제입니다.

- training validation test

머신러닝에서 데이터를 Training, Validation, Test set으로 나누는 이유는 각 단계에서 서로 다른 목적을 위해 데이터를 사용하기 때문입니다. Training set은 모델의 가중치를 학습시키는 데 사용됩니다. Validation set은 학습 중인 모델의 중간 성능을 평가하고, Learning rate나 Layer 깊이 같은 하이퍼파라미터를 튜닝하는 데 사용됩니다. 또한 Overfitting 여부를 모니터링해 Early Stopping 시점을 결정하는 데도 활용됩니다.

Test set을 따로 두는 이유는 Validation set으로 하이퍼파라미터를 튜닝하는 과정에서 모델이 간접적으로 Validation set에 맞춰지기 때문입니다. 따라서 학습과 튜닝 과정에서 전혀 사용되지 않은 데이터로 최종 성능을 평가해야 실제 환경에서의 일반화 성능을 정확히 측정할 수 있습니다. 일반적으로 6:2:2 또는 8:1:1 비율로 나누며, 데이터가 부족할 때는 Training set을 여러 번 나눠 교차 검증하는 K-Fold Cross Validation을 사용하기도 합니다.

- loss function

Loss Function은 모델의 예측값과 실제값 사이의 차이를 측정하는 함수입니다. 역할은 크게 두 가지입니다. 첫째, 모델이 얼마나 잘 예측하는지를 나타내는 성능 지표 역할을 합니다. 둘째, 경사하강법에서 Loss를 최소화하는 방향으로 모델의 가중치를 업데이트하는 기준이 됩니다. 따라서 Loss Function은 모델 학습의 방향을 결정하는 핵심 요소입니다.

대표적으로 회귀 문제에서는 예측값과 실제값 차이를 제곱해 평균을 내는 MSE(Mean Squared Error)를 많이 사용합니다. 제곱을 쓰는 이유는 미분이 용이하고 큰 오차에 더 큰 페널티를 주기 위함입니다. 분류 문제에서는 예측이 확률 분포로 나오기 때문에 단순한 차이로 측정하기 어렵고, 대신 예측 분포와 실제 분포가 얼마나 다른지를 측정하는 Cross-Entropy Loss를 사용합니다.

- 딥러닝과 머신러닝

> 머신러닝은 컴퓨터가 데이터를 기반으로 스스로 패턴을 찾고 예측할 수 있게 만드는 기술입니다. 딥러닝은 머신러닝의 한 분야로, 인공신경망을 기반으로 하는 방식입니다.
> 
> 가장 큰 차이는 특징 추출 방식입니다. 전통적인 머신러닝은 Decision Tree나 SVM 같은 알고리즘을 사용하는데, 이때 사람이 데이터에서 의미 있는 특징을 직접 설계해 모델에 넣어야 합니다. 예를 들어 이미지 분류에서 색상, 질감, 모양 같은 특징을 사람이 먼저 뽑아야 했습니다. 반면 딥러닝은 은닉층이 여러 개 쌓인 깊은 인공신경망 구조를 통해 특징 추출 자체를 자동으로 학습합니다.
> 
> 이 차이 때문에 활용 분야도 달라집니다. 딥러닝은 이미지, 음성, 자연어 같은 비정형 데이터에서 뛰어난 성능을 보입니다. 반면 많은 데이터와 높은 연산 자원이 필요하다는 비용이 발생합니다. 데이터가 적거나 정형 데이터를 다룰 때는 전통적인 머신러닝이 여전히 더 효율적일 수 있습니다.


- nueral network

Neural Network는 사람의 뇌 속 뉴런이 신호를 주고받는 구조에서 영감을 받은 모델입니다. 기본적으로 입력층(Input Layer), 은닉층(Hidden Layer), 출력층(Output Layer)의 세 가지 층으로 구성됩니다.

각 층은 여러 개의 노드, 즉 뉴런으로 이루어져 있습니다. 각 뉴런은 이전 층의 값들에 **가중치(Weight)** 를 곱하고 **편향(Bias)** 을 더한 뒤, **활성화 함수(Activation Function)** 를 거쳐 다음 층으로 값을 전달합니다. 이 과정을 **순전파(Forward Propagation)** 라고 합니다.

학습 과정은 다음과 같습니다. 먼저 순전파로 예측값을 계산하고, Loss Function으로 실제값과의 차이를 측정합니다. 그 다음 **역전파(Backpropagation)** 를 통해 이 오차를 각 층의 가중치에 대해 미분해 어느 방향으로 업데이트할지 계산하고, 경사하강법으로 가중치를 조정합니다. 이 과정을 반복하면서 모델이 점차 정답에 가까워지는 방향으로 학습됩니다.

딥러닝에서 "Deep"은 이 은닉층이 여러 개 쌓인 구조를 의미하며, 층이 깊어질수록 더 추상적이고 복잡한 패턴을 학습할 수 있습니다. 대표적으로 이미지 처리에 특화된 CNN, 순차 데이터에 특화된 RNN, 자연어 처리의 핵심인 Transformer 등이 모두 Neural Network를 기반으로 합니다.

- 활성 함수

활성화 함수의 핵심 역할은 비선형성을 부여하는 것입니다. 가중치 곱과 편향 덧셈만으로 이루어진 Neural Network는 층을 아무리 깊게 쌓아도 결국 하나의 선형 함수와 동일해집니다. 활성화 함수로 비선형성을 추가해야 모델이 이미지나 언어 같은 복잡한 패턴을 학습할 수 있습니다.

대표적인 활성화 함수로 Sigmoid와 ReLU가 있습니다. Sigmoid는 출력을 0과 1 사이로 정규화해 한 뉴런이 지배적이 되는 현상을 막고 확률처럼 해석할 수 있다는 장점이 있습니다. 그래서 이진 분류의 출력층에 주로 사용됩니다. 하지만 Sigmoid를 깊은 층에 반복 적용하면 입력이 크거나 작을 때 기울기가 0에 가까워져 역전파 과정에서 학습이 멈추는 Vanishing Gradient 문제가 발생합니다. 또한 지수 연산 때문에 계산 속도도 느립니다.

이 문제를 해결하기 위해 ReLU가 등장했습니다. ReLU는 양수는 그대로, 음수는 0으로 만드는 단순한 구조여서 연산이 빠르고 양수 영역에서 기울기가 항상 1이기 때문에 Vanishing Gradient 문제를 완화할 수 있습니다. 현대 딥러닝에서는 은닉층에 ReLU 계열 함수를 기본으로 사용하며, 다중 분류의 출력층에는 확률 분포를 반환하는 Softmax를 사용하는 것이 일반적입니다.

- 임베딩

임베딩은 정형·비정형 데이터를 모델이 처리할 수 있는 고정된 크기의 벡터 공간으로 변환하는 것을 의미합니다. 엔지니어링은 숫자를 다루기 때문에 과거부터 데이터를 수치로 표현하려는 노력이 있었고, 아스키 코드로 문자를 숫자로 표현한 것이 대표적인 예시입니다.

과거에는 단어를 표현할 때 One-Hot Encoding을 많이 사용했지만, 차원이 너무 크고 단어 간 의미 관계를 담을 수 없다는 한계가 있었습니다. 현대의 임베딩은 저차원의 밀집 벡터로 데이터를 표현하면서, 의미적으로 유사한 데이터가 벡터 공간에서도 가까이 위치하도록 학습됩니다. 예를 들어 '사과'와 '바나나'의 임베딩은 '사과'와 '강아지'의 임베딩보다 서로 가까워야 합니다.

이러한 벡터 간 유사도를 측정할 때는 코사인 유사도가 대표적으로 사용됩니다. 음성은 주파수 벡터, 이미지는 CNN을 통한 특징 벡터, 자연어는 BERT 계열 모델을 통해 768차원 같은 고차원 벡터로 임베딩됩니다.

저도 KingoM 프로젝트에서 교내 공지사항을 한국어 SBERT로 임베딩해 Pinecone Vector DB에 저장하고, 사용자의 자연어 질문을 임베딩한 뒤 코사인 유사도 기반으로 관련 공지를 검색하는 RAG 구조를 직접 구현한 경험이 있습니다.

- fine tuning 과 pre training

Pre-training과 Fine-tuning은 현대 딥러닝, 특히 대규모 언어 모델에서 핵심이 되는 학습 방식입니다.

Pre-training은 대규모 범용 데이터로 모델에게 일반적인 지식을 먼저 학습시키는 단계입니다. 예를 들어 GPT나 BERT 같은 모델은 인터넷의 방대한 텍스트로 사전 학습되어 언어의 문법, 단어 간 관계, 일반 상식 같은 보편적인 패턴을 습득합니다. 이 과정은 수많은 데이터와 막대한 연산 자원을 필요로 합니다.

Fine-tuning은 이렇게 Pre-training된 모델을 특정 도메인이나 작업에 맞게 추가 학습시키는 단계입니다. 범용 모델이 가진 일반 지식을 바탕으로, 상대적으로 적은 양의 도메인 데이터만으로도 특정 작업에 특화된 성능을 낼 수 있습니다.

비유하자면 Pre-training은 대학에서 교양 교육을 받는 단계, Fine-tuning은 입사 후 특정 업무에 맞게 교육받는 단계와 비슷합니다. 이렇게 나누는 이유는 처음부터 특정 목적으로만 학습하면 데이터와 비용이 너무 크기 때문입니다. 이미 일반 지식을 갖춘 모델을 활용하는 이런 방식을 Transfer Learning, 전이 학습이라고 합니다.

저도 KingoM 프로젝트에서 범용 한국어로 Pre-training된 SBERT 모델을 교내 공지사항 도메인에 맞게 Fine-tuning한 경험이 있습니다. 범용 모델과 Fine-tuning된 모델의 검색 정확도 차이를 pytest로 직접 비교하며, Fine-tuning 이후 유사도 기반 검색 품질이 유의미하게 향상되는 것을 확인했습니다.

- 할루

Hallucination은 LLM이 사실이 아닌 정보를 마치 사실인 것처럼 그럴듯하게 생성하는 현상입니다. 한국어로 환각이라고도 불립니다.

발생 원인은 LLM의 구조적 특성에서 기인합니다. LLM은 다음에 올 단어를 확률적으로 예측하는 방식으로 문장을 생성하기 때문에, 사실을 검증하는 것이 아니라 그럴듯한 문장을 만드는 데 최적화되어 있습니다. 따라서 학습 데이터에 없는 정보나 학습 시점 이후의 최신 정보에 대해서도 자신 있게 답변을 만들어내는 경우가 발생합니다.

이를 해결하기 위한 대표적인 방법이 RAG, 즉 Retrieval-Augmented Generation입니다. 신뢰할 수 있는 외부 데이터를 벡터 DB에 저장하고, 사용자 질문과 관련된 정보를 검색해 LLM에 컨텍스트로 제공하는 방식입니다. 모델이 자체 지식에 의존하는 대신 검증된 외부 근거를 바탕으로 답변하게 되어 Hallucination을 크게 줄일 수 있습니다.

그 외에도 "모르는 것은 모른다고 답하라"는 지시를 주는 Prompt Engineering, 특정 도메인 데이터로 추가 학습하는 Fine-tuning, 생성된 답변을 외부 사실과 대조하는 검증 단계 추가 같은 방법들이 있습니다.

저도 KingoM 프로젝트에서 교내 공지사항 검색 서비스를 개발하며 이 문제를 직접 다뤘습니다. 범용 LLM만 사용하면 존재하지 않는 공지를 만들어내거나 오래된 정보를 제공하는 Hallucination이 발생할 수 있어, Pinecone Vector DB에 실제 공지사항을 저장하고 이를 검색해 LLM에 전달하는 RAG 구조를 직접 구현했습니다. 이를 통해 사용자가 실제로 존재하는 공지를 출처와 함께 확인할 수 있게 만들었습니다.
