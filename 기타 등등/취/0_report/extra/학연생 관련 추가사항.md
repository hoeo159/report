**[Trouble Shooting]**

- **Fourier-Bessel series 후보 폐기 결정**: 원형 대칭이 강점이었던 `1-(x²+y²)` 모델은 좌표 이동(`||r-dr||`) 분리를 위해 Graf's addition formula를 적용해야 했고 추가 M-summation이 발생, Colab CPU 환경 N=M=100 기준 약 28분이 소요됨. 표현 정확도는 좋았지만 실시간 성능 목표와 맞지 않아 erf 다항 근사로 적분이 가능한 2D Gaussian으로 전환
- **정규화 인자 κ 부호 버그**: 2D Fourier series의 정규화 인자 κ 분기를 `n==0 || m==0` 으로 잘못 작성해 x·y 축 방향으로 intensity가 stripe처럼 늘어지는 현상 발생. `!n || !m`으로 수정해 등방 분포 복원
- **Intensity saturation 문제**: 결과 텍스처를 단순 clamp로 잘랐을 때 고휘도 영역이 뭉개지는 현상이 있어, 결과 텍스처에 mipmap을 build → last_mip의 min/max를 UBO에 저장 → 셰이더에서 동적 정규화하는 방식으로 변경. `bind_base_as(GL_SHADER_STORAGE_BUFFER, ...)` 등 SSBO/UBO 바인딩 핸들링 경험을 함께 확보

**[Trouble Shooting]**

- **Shared memory bank conflict**: 초기 구현은 dimension을 chunk로 쪼개 shared memory에 적재했으나, warp 내 32개 thread가 동일 dimension 인덱스의 centroid 슬롯에 동시 접근해 bank conflict 발생. 분할 단위를 **centroid 기준**으로 전환하고 1 thread block ↔ 1 data point로 매핑, 각 thread가 순차 dimension을 처리하도록 재설계하여 bank conflict 제거 및 K 확장성 확보
- **대용량 데이터의 Disk → GPU 로딩 병목**: CPU 메모리에 한 번에 적재 불가능한 1M+ 데이터셋을 위해 mmap으로 디스크 파일을 가상 메모리에 매핑하고, GPU 메모리를 두 영역으로 나눠 한쪽은 kernel 실행, 다른 한쪽은 다음 batch 업로드를 동시에 수행하는 2-way stream 파이프라인 설계
- **CUDA stream 간 overlap 미발생**: 단순 `cudaMemcpyAsync` + multi-stream 만으로는 nvprof 상에서 stream이 거의 직렬 실행되는 현상을 확인. host buffer를 pinned memory로 고정하고 input/output transfer와 kernel을 분리, CUDA event 기반의 fine-grained synchronization으로 stream dependency를 명시. loop 내 동기화 시 병목, loop 밖 동기화 시 large dataset에서 segfault 발생 케이스를 통해 메모리 lifetime 추적과 stream handler(priority/preemption) 설계의 필요성을 도출하고 후속 과제로 정리
